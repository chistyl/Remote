# TV Remote v1.1.1 測試報告

## 本輪主要修正

依 `chistyl/Remote_ATV` 可取得的 V4.18 Flutter／Android 原始碼核對配對協定後，發現舊版新 APP 有四個會導致配對失敗的協定差異：

1. Pairing envelope protocol version 原為 `1`，參考實作使用 `2`。
2. PairingOptions 多送一個頂層 field 2。
3. PIN SHA-256 proof 漏掉 RSA modulus 與 exponent 間的 `0x00` 分隔位元組。
4. ACK 類型原本錯誤讀取 field 3；參考實作以 field 11、21、31、41 的 presence 判斷。

以上均已修正，並加入獨立 `PairingProtocol` 及回歸測試。另修正電視 DHCP 換 IP 時的憑證指紋比對策略，並替 TCP connect 加入 8 秒逾時。

## 已執行並通過

- `ProtoCodec.kt` + `PairingProtocol.kt` 獨立 Kotlin 編譯。
- 配對封包版本／狀態／訊息欄位固定測試。
- PairingOptions 欄位形狀測試。
- PIN proof 固定 SHA-256 測試向量：`F4B2C3` 對應 `f44ec492…796f3923`。
- 錯誤 PIN check byte 拒絕測試。
- 非 200 配對狀態拒絕測試。
- `PairingClient.kt`、`RemoteClient.kt`、`KeyCodes.kt` 搭配 Android Log、憑證及 TLS 替身類別與 Kotlin Coroutines 編譯通過。
- `TlsFactory.kt` 搭配憑證替身類別編譯通過。
- Android Manifest XML 與專案資源 XML 格式檢查通過。
- 舊版不正確的 `readType()` 及錯誤配對 envelope 組裝程式已移除。
- ZIP 完整性檢查通過。

## 尚未執行

- Android Gradle 全專案編譯、`testDebugUnitTest`、APK 產生。

原因：目前工作環境沒有 Android SDK／Gradle，也沒有實體 ADB 裝置。純 Kotlin／替身類別編譯不能代替完整 Android 建置或實機測試。
